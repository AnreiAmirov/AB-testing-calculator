How to solve a problem at an interview

Interviewers rarely judge only whether you reach the answer. They watch how you think: whether you clarify the task, start from something that works, and improve it deliberately. Silence for ten minutes followed by perfect code scores worse than reasoning aloud and arriving at a good solution. Six steps make that process visible.

  1. ClarifyRestate the task in your own words. Ask about the edges: can the array be empty? Are there negatives or duplicates? Is the input sorted? Each answer can change the solution.
  2. Work an example by handTake a small input and solve it on paper. This is where you notice the pattern — and catch a misunderstanding before writing a line of code.
  3. Say the brute forceDescribe the obvious solution and its complexity, even if it is slow. It proves you understand the task and gives a baseline to improve on.
  4. Find the bottleneckAsk what work is repeated. Usually it is a nested loop re-scanning data you have already seen — the classic place where a dictionary, two pointers or a running sum helps.
  5. Write the codeClear names, small steps, comments where intent is not obvious. Readable code is part of the grade, not decoration.
  6. Test it yourselfWalk through your example line by line, then the edges: empty input, one element, all equal values. Finding your own bug is a plus; the interviewer finding it is a minus.
The most common mistake is jumping straight to code. Two minutes spent clarifying and working an example save twenty minutes of rewriting a solution to the wrong problem.
Complexity: what Big-O actually means

Big-O answers one question: when the input grows, how fast does the work grow? It does not measure seconds — those depend on the computer. It describes the shape of growth. O(n) means "twice the data, twice the work". O(n²) means "twice the data, four times the work".

The chart shows why this matters more than any micro-optimisation. On small inputs every approach is fast. As the data grows, O(n²) leaves the others behind — and that is the curve your interviewer wants you to avoid.

ComplexityWhat it looks like in codeExample
O(1)A fixed number of steps, regardless of sizeReading a dict value by key
O(log n)The search space halves at every stepBinary search in a sorted array
O(n)One pass over the dataSum of a list, finding the maximum
O(n log n)Sorting, or log n work for each elementsorted()
O(n²)A loop inside a loop over the same dataComparing every pair
A real measurement, not a promise

Both functions below solve Two Sum. I timed them on arrays of growing length, on the worst case where no answer exists and every element must be checked. The numbers are measured, not modelled.

def two_sum_brute(nums, target):
    for i in range(len(nums)):
        for j in range(i + 1, len(nums)):   class="tok-c"># every pair
            if nums[i] + nums[j] == target:
                return [i, j]
    return []

def two_sum(nums, target):
    seen = {}                          class="tok-c"># value -> index
    for i, x in enumerate(nums):
        need = target - x
        if need in seen:
            return [seen[need], i]
        seen[x] = i
    return []
Look at the step from 2,000 to 4,000 elements: the input doubled, the nested loops became roughly four times slower, and the dictionary only twice as slow. That is O(n²) against O(n) — visible in real milliseconds.
Memory counts too. The fast solution stores up to n values in a dictionary — O(n) extra memory. That is the usual trade: spend memory to save time. Interviewers often ask "can you do it with O(1) memory?" — be ready to say what it would cost.

1Two Sum
Arrays & hashingEasy#1 Open on LeetCode ↗
The task

Given a list of numbers and a target, return the positions of the two numbers that add up to the target. Exactly one such pair exists, and you may not use the same element twice.

nums = [3, 8, 11, 5, 4], target = 9 → [3, 4] # 5 + 4
The obvious approach

Check every pair with two nested loops. It works, but for n numbers that is about n²/2 comparisons — 50 million for 10,000 elements.

The key insight
For each number x we already know exactly which partner we need: target − x. So instead of searching for it, we remember every number we have passed in a dictionary and simply ask "have I seen my partner?" — an instant lookup.
Step by step
#ixneed = target − xseenneed in seen?
1036{}—
2181{3:0}—
3211-2{3:0, 8:1}—
4354{3:0, 8:1, 11:2}—
5445{3:0, 8:1, 11:2, 5:3}✓ → [3, 4]

Read row 5: when we reach 4, its partner is 5 — and 5 is already in seen at position 3. One pass, done.

The solution
def two_sum(nums, target):
    seen = {}                          class="tok-c"># value -> index
    for i, x in enumerate(nums):
        need = target - x
        if need in seen:
            return [seen[need], i]
        seen[x] = i
    return []
ComplexityO(n) time · O(n) memory
Where people slip
Adding the number to seen before checking for its partner. With target 10 and the number 5, the code would pair 5 with itself.
Where this shows up in analytics
This is exactly how a hash JOIN works in a database: build a lookup from one table, then walk the other once. It is also how you reconcile two payments that should net to zero.
2Container With Most Water
Two pointersMedium#11 Open on LeetCode ↗
The task

Each number is the height of a vertical wall. Pick two walls so that, together with the floor, they hold the most water. The water level is set by the lower wall, and the width is the distance between them.

height = [1, 8, 6, 2, 5, 4, 8, 3, 7] → 49 # min(8, 7) × (8 − 1)
The obvious approach

Try every pair of walls — O(n²). Correct, but slow, and it ignores a property of the problem that lets us discard most pairs.

The key insight
Start with the widest container: one pointer at each end. Now ask which wall to move. The water is limited by the lower wall. Moving the taller one can only make things worse — the width shrinks while the limit stays the same. So we always move the lower wall inward, and never miss the best answer.
Step by step
012345678
11L86254837Rarea=8 best=8 L→
218L6254837Rarea=49 best=49 ←R
318L625483R7area=18 best=49 ←R
418L62548R37area=40 best=49 ←R
518L6254R837area=16 best=49 ←R
618L625R4837area=15 best=49 ←R
718L62R54837area=4 best=49 ←R
818L6R254837area=6 best=49 ←R

Each row is one step. L and R are the pointers, the shaded cells are the current container. On step 2 the area reaches 49, and nothing later beats it.

The solution
def max_area(height):
    left, right = 0, len(height) - 1
    best = 0
    while left < right:
        h = min(height[left], height[right])
        best = max(best, h * (right - left))
        if height[left] < height[right]:
            left += 1
        else:
            right -= 1
    return best
ComplexityO(n) time · O(1) memory
Where people slip
Moving the taller wall, or moving both at once. Both can skip the optimal pair.
Where this shows up in analytics
Two pointers on sorted data is how you match two ordered lists in one pass — for example, pairing each event with the nearest session boundary without a nested loop.
3Longest Substring Without Repeating Characters
Sliding windowMedium#3 Open on LeetCode ↗
The task

Find the length of the longest stretch of a string in which no character appears twice.

s = "abcabcbb" → 3 # "abc"
The obvious approach

Check every substring and test whether its characters are unique — O(n³), or O(n²) with care.

The key insight
Keep a window that is always valid: no repeats inside. Extend it one character at a time to the right. When the new character already sits inside the window, jump the left edge just past its previous position. The window never moves backwards, so each character is handled once.
Step by step
01234567
1a▼bcabcbblen=1 best=1
2ab▼cabcbblen=2 best=2
3abc▼abcbblen=3 best=3
4abca▼bcbblen=3 best=3 a in window → start=1
5abcab▼cbblen=3 best=3 b in window → start=2
6abcabc▼bblen=3 best=3 c in window → start=3
7abcabcb▼blen=2 best=3 b in window → start=5
8abcabcbb▼len=1 best=3 b in window → start=7

The shaded cells are the window, ▼ marks the new character. On step 4 the second a arrives, so the window jumps forward and stays repeat-free.

The solution
def length_of_longest_substring(s):
    last_seen = {}                      class="tok-c"># char -> last index
    start = best = 0
    for i, ch in enumerate(s):
        if ch in last_seen and last_seen[ch] >= start:
            start = last_seen[ch] + 1   class="tok-c"># jump past the repeat
        last_seen[ch] = i
        best = max(best, i - start + 1)
    return best
ComplexityO(n) time · O(k) memory
Where people slip
Forgetting the check last_seen[ch] >= start. Without it, a character seen before the window would wrongly pull the left edge backwards.
Where this shows up in analytics
A sliding window is every rolling metric you compute: 7-day active users, a 30-minute session, a moving average. Same idea — add what enters, drop what leaves.
4Valid Parentheses
StackEasy#20 Open on LeetCode ↗
The task

A string contains only brackets of three kinds. Decide whether every bracket is closed by the same kind, in the correct order.

"{[()]}" → True "{[(])}" → False "{[()]}(" → False
The obvious approach

Repeatedly delete adjacent pairs like () until nothing changes, then check whether the string is empty. It works, but each pass rescans the whole string — O(n²).

The key insight
The bracket that must close next is always the most recently opened one. That "last in, first out" rule is exactly what a stack does: push each opening bracket, and on a closing one pop the top and check that it matches.
Step by step
#charactionstack
1{push {{
2[push [{[
3(push ({[(
4)pop ( ✓{[
5]pop [ ✓{
6}pop { ✓∅
7(push ((
8·stack == [] ?( → False

The first six characters pair up perfectly and the stack empties. Then a lone ( arrives and is never closed — the stack is not empty at the end, so the answer is False.

The solution
def is_valid_parentheses(s):
    pairs = {")": "(", "]": "[", "}": "{"}
    stack = []
    for ch in s:
        if ch in "([{":
            stack.append(ch)
        elif not stack or stack.pop() != pairs[ch]:
            return False
    return not stack
ComplexityO(n) time · O(n) memory
Where people slip
Two edge cases: a closing bracket when the stack is empty (crashes on pop), and opening brackets left over at the end. Both must return False.
Where this shows up in analytics
Stacks validate any nested structure: JSON and XML, nested funnel steps, or undo history in a product. Whenever "the last thing opened closes first", reach for a stack.
5Binary Search
Binary searchEasy#704 Open on LeetCode ↗
The task

Find the position of a value in a sorted list, or return −1 if it is not there.

nums = [2, 5, 8, 12, 16, 23, 38, 56, 72, 91], target = 23 → 5
The obvious approach

Scan from the start until you find it — O(n). It ignores the one thing the task gives you for free: the list is sorted.

The key insight
Look at the middle element. Because the list is sorted, one comparison tells you which half the target must be in — and you can throw the other half away. Each step halves the search space, so a million elements take at most 20 steps.
Step by step
0123456789
12L581216M2338567291Rnums[4]=16 < 23 L = M + 1
2258121623L3856M7291Rnums[7]=56 > 23 R = M − 1
3258121623M38R567291nums[5]=23 = target ✓

L, M and R are left, middle and right. The shaded area is what is still being searched — watch it halve on every row until the middle lands on 23.

The solution
def binary_search(nums, target):
    left, right = 0, len(nums) - 1
    while left <= right:
        mid = (left + right) // 2
        if nums[mid] == target:
            return mid
        if nums[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return -1
ComplexityO(log n) time · O(1) memory
Where people slip
Off-by-one errors: writing left < right instead of <= skips the last candidate, and left = mid instead of mid + 1 loops forever.
Where this shows up in analytics
Binary search is how a database index finds a row without scanning the table — and how you find the smallest sample size that reaches a target power without trying every value.
6Maximum Subarray
GreedyMedium#53 Open on LeetCode ↗
The task

Find the contiguous stretch of numbers with the largest possible sum, and return that sum.

nums = [-2, 1, -3, 4, -1, 2, 1, -5, 4] → 6 # [4, -1, 2, 1]
The obvious approach

Sum every possible stretch — O(n²) even with a running total, O(n³) without one.

The key insight
Walk once and keep the best sum of a stretch ending here. At each number there is one decision: extend the previous stretch, or start fresh from this number. If the previous stretch is negative, it can only drag you down, so you drop it. This is Kadane's algorithm.
Step by step
#xcurrent + xdecisioncurrentbest
1-2—start-2-2
21-1restart11 ✓
3-3-2extend-21
442restart44 ✓
5-13extend34
625extend55 ✓
716extend66 ✓
8-51extend16
945extend56

Look at the decision column (extend the stretch, or restart it). On row 2 the running sum was −2, so starting fresh from 1 is better. On row 4 it restarts again — a stretch summing to −2 cannot help the 4. From there the stretch only extends, and best reaches 6 on row 7.

The solution
def max_subarray(nums):
    current = best = nums[0]
    for x in nums[1:]:
        current = max(x, current + x)   class="tok-c"># extend or start over
        best = max(best, current)
    return best
ComplexityO(n) time · O(1) memory
Where people slip
Starting best at 0. If every number is negative, the answer is the largest negative number, not 0.
Where this shows up in analytics
This finds the most profitable run in a P&L series, or the strongest consecutive period of a campaign — any time you need the best contiguous stretch of a metric.
7Product of Array Except Self
Prefix sumsMedium#238 Open on LeetCode ↗
The task

For every position, return the product of all the other numbers — without using division.

nums = [1, 2, 3, 4] → [24, 12, 8, 6]
The obvious approach

For each position, multiply everything else — O(n²). Division would be O(n), but it is forbidden and breaks on zeros anyway.

The key insight
The product of everything except position i is (everything to the left) × (everything to the right). One pass left-to-right collects the left products; a second pass right-to-left multiplies in the right products. Two passes, no division.
Step by step
#passinums[i]multiplieranswer
1→01prefix=1[1, 1, 1, 1]
2→12prefix=1[1, 1, 1, 1]
3→23prefix=2[1, 1, 2, 1]
4→34prefix=6[1, 1, 2, 6]
5←34suffix=1[1, 1, 2, 6]
6←23suffix=4[1, 1, 8, 6]
7←12suffix=12[1, 12, 8, 6]
8←01suffix=24[24, 12, 8, 6] ✓

Rows marked → are the first pass: each slot gets the product of everything before it. Rows marked ← are the second: each slot is multiplied by everything after it. The last row is the answer.

The solution
def product_except_self(nums):
    n = len(nums)
    answer = [1] * n
    prefix = 1
    for i in range(n):                  class="tok-c"># left-to-right: product of everything before i
        answer[i] = prefix
        prefix *= nums[i]
    suffix = 1
    for i in range(n - 1, -1, -1):      class="tok-c"># right-to-left: times everything after i
        answer[i] *= suffix
        suffix *= nums[i]
    return answer
ComplexityO(n) time · O(1) extra memory
Where people slip
Reaching for division. Besides being forbidden, a single zero in the array makes it divide by zero.
Where this shows up in analytics
Prefix and suffix accumulation is how you compute cumulative revenue, running retention and "share of total up to this point" in a single pass — the same thing a window function does in SQL.
8Merge Intervals
IntervalsMedium#56 Open on LeetCode ↗
The task

Given a list of time ranges, merge all the ones that overlap and return the result.

[[1,3], [8,10], [2,6], [15,18], [9,11]] → [[1,6], [8,11], [15,18]]
The obvious approach

Compare every interval with every other and merge repeatedly until nothing changes — O(n²) or worse.

The key insight
Sort by start time first. Once sorted, an interval can only overlap the one directly before it. Walk through: if the next interval starts before the current one ends, stretch the current end; otherwise begin a new block.
Step by step
sorted(intervals, key=start)
[1, 3]
[2, 6]
[8, 10]
[9, 11]
[15, 18]
merged
[1, 6][8, 11][15, 18]
1357911131517

Top: the intervals after sorting. Bottom: the result. [1,3] and [2,6] overlap and fuse into [1,6]; [8,10] and [9,11] fuse into [8,11]; [15,18] stands alone.

The solution
def merge_intervals(intervals):
    intervals = sorted(intervals, key=lambda iv: iv[0])
    merged = []
    for start, end in intervals:
        if merged and start <= merged[-1][1]:
            merged[-1][1] = max(merged[-1][1], end)
        else:
            merged.append([start, end])
    return merged
ComplexityO(n log n) time — the sort dominates
Where people slip
Setting the merged end to the new interval's end instead of the maximum of the two. An interval fully inside another would shrink the block.
Where this shows up in analytics
This is how you compute total active time from overlapping sessions, or a customer's real subscription coverage when plans overlap — the same logic as gap-and-island problems in SQL.
9Climbing Stairs
Dynamic programmingEasy#70 Open on LeetCode ↗
The task

You climb a staircase of n steps, taking 1 or 2 steps at a time. In how many different ways can you reach the top?

n = 3 → 3 # 1+1+1, 1+2, 2+1
The obvious approach

Recursion: ways(n) = ways(n−1) + ways(n−2). Correct, but it recomputes the same values again and again — exponential time, about 1.6ⁿ calls.

The key insight
To stand on step k, your last move came from step k−1 or step k−2. So ways(k) = ways(k−1) + ways(k−2). Compute it from the bottom up and remember each answer once. That is the whole idea of dynamic programming: solve small subproblems, reuse them.
Step by step
#step khowways[k]
11base case1
22base case2
33ways[2] + ways[1] = 2 + 13
44ways[3] + ways[2] = 3 + 25
55ways[4] + ways[3] = 5 + 38
66ways[5] + ways[4] = 8 + 513
77ways[6] + ways[5] = 13 + 821 ✓

Each row is built from the two above it. Step 7 has 21 ways — reached in 7 steps instead of the dozens of repeated calls plain recursion would make.

The solution
def climb_stairs(n):
    if n <= 2:
        return n
    prev, curr = 1, 2
    for _ in range(3, n + 1):
        prev, curr = curr, prev + curr
    return curr
ComplexityO(n) time · O(1) memory
Where people slip
Wrong base cases. With 1 step there is 1 way, with 2 steps there are 2. Getting these wrong shifts every answer that follows.
Where this shows up in analytics
Dynamic programming is behind sequence alignment, optimal budget allocation across channels, and counting paths through a funnel — any problem where the best answer is built from smaller best answers.

2Group Anagrams
Arrays & hashingMedium#49 Open on LeetCode ↗

Group words that are made of exactly the same letters, in any order.

["eat","tea","tan","ate","nat","bat"] → [["eat","tea","ate"], ["tan","nat"], ["bat"]]
Anagrams become identical once their letters are sorted. Use that sorted form as a dictionary key.
def group_anagrams(words):
    groups = defaultdict(list)
    for w in words:
        groups["".join(sorted(w))].append(w)
    return list(groups.values())
Why it works
Every word is filed under its sorted letters, so anagrams land in the same bucket. This is grouping by a computed key — exactly what groupby does.

3Valid Palindrome
Two pointersEasy#125 Open on LeetCode ↗

Ignoring case and every non-alphanumeric character, decide whether a string reads the same forwards and backwards.

"A man, a plan, a canal: Panama" → True "race a car" → False
Put one pointer at each end and move them towards each other, skipping anything that is not a letter or digit.
def is_palindrome(s):
    left, right = 0, len(s) - 1
    while left < right:
        while left < right and not s[left].isalnum():
            left += 1
        while left < right and not s[right].isalnum():
            right -= 1
        if s[left].lower() != s[right].lower():
            return False
        left += 1
        right -= 1
    return True
Why it works
The pointers compare matching positions from both ends without building a cleaned copy, so memory stays O(1).
Tests to check yourself
is_palindrome("A man, a plan, a canal: Panama")
is_palindrome("race a car")
is_palindrome(" ")

43Sum
Two pointersMedium#15 Open on LeetCode ↗

Find every unique triple of numbers that sums to zero. The same triple must not appear twice.

[-1, 0, 1, 2, -1, -4] → [[-1, -1, 2], [-1, 0, 1]]
Sort first. Fix one number, then look for the other two with two pointers on the rest of the array. Skip equal neighbours to avoid duplicates.
def three_sum(nums):
    nums = sorted(nums)
    res = []
    for i in range(len(nums) - 2):
        if i > 0 and nums[i] == nums[i - 1]:
            continue                       class="tok-c"># skip duplicate anchors
        left, right = i + 1, len(nums) - 1
        while left < right:
            s = nums[i] + nums[left] + nums[right]
            if s < 0:
                left += 1
            elif s > 0:
                right -= 1
            else:
                res.append([nums[i], nums[left], nums[right]])
                left += 1
                right -= 1
                while left < right and nums[left] == nums[left - 1]:
                    left += 1
    return res
Why it works
Sorting turns "find two numbers summing to −x" into the two-pointer problem: too small → move left up, too big → move right down. Overall O(n²), down from O(n³).
Tests to check yourself

three_sum([0, 1, 1])

5Best Time to Buy and Sell Stock
Sliding windowEasy#121 Open on LeetCode ↗

Given daily prices, choose one day to buy and a later day to sell for the biggest profit. If no profit is possible, return 0.

[7, 1, 5, 3, 6, 4] → 5 # 6 − 1 [7, 6, 4, 3, 1] → 0
Walk through the days once, remembering the lowest price so far. Today's best profit is today's price minus that minimum.
def max_profit(prices):
    lowest = float("inf")
    best = 0
    for p in prices:
        lowest = min(lowest, p)
        best = max(best, p - lowest)
    return best
Why it works
The best sale on any day uses the cheapest earlier day, so tracking the running minimum is enough. When prices only fall, the profit never rises above 0.
Tests to check yourself
max_profit([7, 1, 5, 3, 6, 4])
max_profit([7, 6, 4, 3, 1])
# tests (all passed):>>> max_profit([7, 1, 5, 3, 6, 4]) 5 >>> max_profit([7, 6, 4, 3, 1]) 0
6Maximum Average Subarray I
Sliding windowEasy#643 Open on LeetCode ↗

Find the contiguous stretch of exactly k numbers with the highest average, and return that average.

nums = [1, 12, -5, -6, 50, 3], k = 4 → 12.75
Do not re-add k numbers for every window. When the window slides one step, add the new number and subtract the one that left.
def find_max_average(nums, k):
    window = sum(nums[:k])
    best = window
    for i in range(k, len(nums)):
        window += nums[i] - nums[i - k]
        best = max(best, window)
    return best / k
Why it works
Each slide costs two operations instead of k, so the whole scan is O(n) — the same trick as a 7-day rolling average.

7Daily Temperatures
StackMedium#739 Open on LeetCode ↗

For each day, return how many days you must wait for a warmer temperature. If it never gets warmer, return 0 for that day.

[73, 74, 75, 71, 69, 72, 76, 73] → [1, 1, 4, 2, 1, 1, 0, 0]
Keep a stack of days still waiting for a warmer one. When a warm day arrives, it resolves every colder day on top of the stack.
def daily_temperatures(temps):
    answer = [0] * len(temps)
    stack = []                          class="tok-c"># indices of days still waiting
    for i, t in enumerate(temps):
        while stack and temps[stack[-1]] < t:
            j = stack.pop()
            answer[j] = i - j
        stack.append(i)
    return answer
Why it works
Each day is pushed once and popped once, so the total work is O(n) even though there is a loop inside a loop. This is the "monotonic stack" pattern.

8Min Stack
StackMedium#155 Open on LeetCode ↗

Design a stack that supports push, pop, top, and returning the current minimum — every operation in constant time.

push(-2), push(0), push(-3) → get_min() = -3; pop() → get_min() = -2
Store, next to every value, what the minimum was at the moment it was pushed.
class MinStack:
    def __init__(self):
        self.items = []                 class="tok-c"># pairs: (value, min so far)
    def push(self, x):
        current_min = min(x, self.items[-1][1]) if self.items else x
        self.items.append((x, current_min))
    def pop(self):
        self.items.pop()
    def top(self):
        return self.items[-1][0]
    def get_min(self):
        return self.items[-1][1]
Why it works
Each entry carries its own snapshot of the minimum, so popping automatically restores the previous minimum — no searching required.

9Search Insert Position
Binary searchEasy#35 Open on LeetCode ↗

In a sorted list, return the index of the target if it exists, or the index where it would be inserted to keep the list sorted.

[1, 3, 5, 6], 5 → 2 [1, 3, 5, 6], 2 → 1 [1, 3, 5, 6], 7 → 4
Binary search for the first position whose value is not less than the target.
def search_insert(nums, target):
    left, right = 0, len(nums)
    while left < right:
        mid = (left + right) // 2
        if nums[mid] < target:
            left = mid + 1
        else:
            right = mid
    return left
Why it works
Whether or not the target exists, "the first element ≥ target" is exactly where it belongs. Python's bisect_left does this.

11Jump Game
GreedyMedium#55 Open on LeetCode ↗

Each number is the maximum jump length from that position. Starting at the first index, can you reach the last one?

[2, 3, 1, 1, 4] → True [3, 2, 1, 0, 4] → False
Track the furthest index you can reach so far. If you ever stand beyond it, you are stuck.
def can_jump(nums):
    reach = 0
    for i, step in enumerate(nums):
        if i > reach:
            return False
        reach = max(reach, i + step)
    return True
Why it works
Being greedy is safe here: you never need to know how you reached a position, only the furthest point you can still reach.

class NumArray:

15Insert Interval
IntervalsMedium#57 Open on LeetCode ↗

A list of non-overlapping intervals is sorted by start. Insert a new interval, merging wherever needed, and keep the result sorted.

[[1,3], [6,9]] + [2,5] → [[1,5], [6,9]]
Three phases: copy everything that ends before the new one starts, merge everything that overlaps it, then copy the rest.
def insert_interval(intervals, new):
    res = []
    i, n = 0, len(intervals)
    while i < n and intervals[i][1] < new[0]:
        res.append(intervals[i]); i += 1
    start, end = new
    while i < n and intervals[i][0] <= end:
        start = min(start, intervals[i][0])
        end = max(end, intervals[i][1])
        i += 1
    res.append([start, end])
    res.extend(intervals[i:])
    return res
Why it works
Because the input is already sorted, a single pass is enough — no re-sorting, O(n).

16Non-overlapping Intervals
IntervalsMedium#435 Open on LeetCode ↗

Return the minimum number of intervals to remove so that the rest do not overlap. Touching at an endpoint is allowed.

[[1,2], [2,3], [3,4], [1,3]] → 1 # − [1,3]
Sort by end time and always keep the interval that finishes earliest — it leaves the most room for the rest.
def erase_overlap_intervals(intervals):
    intervals = sorted(intervals, key=lambda iv: iv[1])
    removed = 0
    last_end = float("-inf")
    for start, end in intervals:
        if start >= last_end:
            last_end = end              class="tok-c"># keep it
        else:
            removed += 1                class="tok-c"># overlaps: drop it
    return removed
Why it works
Choosing the earliest finish is the classic greedy proof: any other choice can be swapped for it without losing a single interval.

def rob(nums):

    for x in nums:
        take, skip = skip + x, max(take, skip)
    return max(take, skip)

The best total up to here depends only on the two previous best totals, so two variables replace a whole table — O(n) time, O(1) memory.

18Coin Change
Dynamic programmingMedium#322 Open on LeetCode ↗

Given coin denominations, find the fewest coins that make up an amount, or return −1 if it cannot be done.

coins = [1, 2, 5], amount = 11 → 3 # 5 + 5 + 1
Build a table: the fewest coins for every amount from 0 up. For each amount, try every coin as the last one.
def coin_change(coins, amount):
    INF = amount + 1
    dp = [0] + [INF] * amount
    for a in range(1, amount + 1):
        for c in coins:
            if c <= a:
                dp[a] = min(dp[a], dp[a - c] + 1)
    return dp[amount] if dp[amount] != INF else -1
Why it works
Greedy fails here — with coins [1, 3, 4] and amount 6 it picks 4+1+1, while 3+3 is better. Dynamic programming checks every option once and finds the true minimum.

How to practise so it sticks

Solving a hundred problems once teaches less than solving thirty properly. A few habits make the difference.

  • Learn the pattern, not the answer. After each problem, write one sentence: "this was a sliding window because…". That sentence is what you will recall at the interview.
  • Give yourself 25 minutes. If you are stuck after that, open the hint. Still stuck after 10 more — read the solution, then solve it again from scratch the next day.
  • Talk out loud. Practise explaining your reasoning as you go. At an interview, silent coding is the most common way to lose points you actually earned.
  • Revisit after a week. Spaced repetition beats volume. A problem you can still solve seven days later is a problem you have learnt.
  • Always state the complexity. Finish every solution by saying its time and memory cost. Interviewers expect it, and it forces you to check whether there is a faster way.
