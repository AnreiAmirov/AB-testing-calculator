    Which file works

    Per user — one row per user: date, group, metric value (revenue, or 0/1 for “converted”). The sample dataset looks like this.

    date,user_id,group,revenue
2026-09-07,u100000,A,0
2026-09-07,u100006,B,2079

    Daily totals — one row per day and group: users, then mean and standard deviation and/or the number of conversions.

    date,group,users,mean,sd,conversions
2026-09-07,A,1573,154.5,787.6,114
2026-09-07,B,1613,211.4,872.1,146

    Columns are recognised by name (date / дата, group / группа, revenue / value / converted / значение — or users, mean, sd, conversions). Separator: comma or semicolon. There must be exactly two groups; A or control is treated as the control — swap them with the button on the right. Conversion = the share of users with a value above zero.

    The sample is synthetic: a true +6% lift in conversion plus a temporary novelty effect in the first week. Every day is computed on all data accumulated up to that day: Welch’s t-test for the mean, the Z-test for conversion — the same tests as in “Final totals”.

    Step 3 · Parameters
    Aggregate to one value per user before pasting. For AOV: each user's total revenue ÷ their number of orders. For CTR per session: each user's total clicks ÷ their total sessions. Running a t-test on raw transaction rows (not aggregated) inflates false positives by 2–10×.
    Why does this matter?
    • A heavy buyer with 10 orders contributes 10 rows if not aggregated — their data dominates, creating correlation between rows that breaks the independence assumption of t-tests.
    • The standard error becomes 2–10× too small, making results look far more significant than they are. False positive rate can exceed 30%.
    • Fix: compute one value per user (total revenue ÷ total orders), then paste those per-user values below.
